# 循环教师与无循环蒸馏：实验复盘及下一阶段计划

记录日期：2026-11-17。本文件记录目前的判断和待验证假设，不表示新方案已实现或取得收益。

## 目标和当前证据

最终目标是：训练时利用文字推理步骤，推理时不生成思维链、不插入 latent 位置、不执行额外循环，仍能显著提高 GSM-MC 直接选择答案的准确率。分两阶段：先得到**在相同直接答题任务上显著强于单次前向的循环教师**，再尝试将其能力蒸馏到普通单次前向学生。不能仅凭循环路径的绝对分数，或者辅助损失下降，就认为第一阶段完成。

## 与 GLR 的差别

当前 Qwen3-1.7B 有 28 个 decoder 层，代码对第 `[9,18)` 层的 9 层块重复 3 次，前部 9 层和后部 10 层各运行一次，因此同一输入位置的主路径运行 `9 + 9*3 + 10 = 46` 次层计算；与无循环的 28 次相比，增加 18 次。启用 damping 时，每轮更新为 `h + (G(h)-h)/loop_count`，所以增加轮数也改变单轮步长。循环更新对整个已有序列生效，但监督主要读最后的答案槽。详见 `src/loop_jev/looping.py`。

[GLR 论文 v2](https://arxiv.org/html/2606.02248v2) 和 [官方代码](https://github.com/idiap/GLR) 的 `K=10` 指的是 **10 个顺序添加的连续思考位置**：每个新位置作为模型输入，经过完整 Transformer，最后的隐藏状态经一个线性头预测输入 embedding 空间的下一步位移。训练锚点是相邻文字 CoT token 的 embedding 差；训练采用将预测 embedding 替换思考 span 后再前向的机制，并继续监督后续文本。其实现的数学目标、token 位置、可用上下文及评估方式均不同于我们的中间块循环及“不同 CoT 前缀的隐藏向量差”。GLR 的性能重点是受限生成预算下的正确率/生成长度权衡，连续步骤后仍可能生成文字，并未证明关闭所有额外思考计算后直接输出答案仍有收益。`3` 和 `10` 不能直接当作同类轮数比较；整段输入重复层块和 KV-cache 下逐个新增位置的 FLOPs、延迟及峰值显存也不同。

相比之下，[LOTUS 论文](https://arxiv.org/html/2606.31779v2) 在题目与答案之间放置多个并行的 latent 位置/块，迭代更新后，用 LM head 在这些位置上预测对齐的文字推理 token，并对答案单独监督。这提供更贴近我们第一阶段的**工作区 + 可解码过程监督**思路；其论文准确率及思考阶段加速并不能直接推断我们 GSM-MC 单字母预测的收益。

[KaVa 论文 v2](https://arxiv.org/html/2510.02312v2) 提供另一种更直接的过程表征目标：文字 CoT 教师前向产生各层、各头的 K/V 缓存；按冗余度与答案注意力选取少量 K/V 对，形成与 latent 位置数量相同的压缩目标；学生只看题目，迭代更新 latent 位置，以答案 CE 和学生 K/V 到压缩目标的损失训练。其报告的设置是 24 个 latent 位置、3 次并行迭代；两种预算应分开比较。论文还指出额外迭代并不单调提高准确率，对训练数据量敏感。它的原始方法包含与本项目不同的模型、数据量、推理接口和压缩过程，不能直接移植论文中的准确率。

KaVa 的启发是**让中间工作区承载对答案有用的压缩推理上下文**，不必逐 token 重建整条文字 CoT。与此前只比较不同上下文的一个答案槽 hidden 向量不同，KV 目标直接关系到下游答案槽能从哪些位置读取信息；但即使这样也不保证会提高我们的直接答题准确率。

## 第一阶段：验证真正有用的循环计算

1. **先建立评估门槛。** 固定底模、训练样本、随机种子、优化步数、答案提示及评估后端；从训练集划出验证集用于选择结构和轮数，最终仅在固定 test 集报告。至少比较同权重关闭循环的消融、匹配设置单次前向模型，以及有循环模型；检查循环增益随轮数是否形成可解释的趋势。目标是预先约定足够大的准确率增益（例如至少 3 个百分点），并用多个训练种子和汇总指标确认，而非按逐题预测变化解读；同时记录延迟和训练/推理峰值显存。
2. **低成本结构检查。** 先实现仅改变评估轮数的探针，在已有循环模型上检查 `K=1/2/3/...`，作为诊断；当前评估命令尚不支持直接覆盖检查点轮数。由于当前 damping 的分母取 `K`，且模型只按某个固定轮数训练，这些跨预算探针不构成严格训练对照。若有迹象，再分别训练预算匹配模型，或实现可变预算训练；记录总层计算及显存，不能只列 `K`。
3. **主要新实验：增加 latent 工作区。** 在题目/选项与答案读出之间加入少量占位 latent 位置，使这些位置同样参与中间块循环；推理时不出现 gold CoT。优先尝试 KaVa 启发的压缩 KV 过程监督：冻结同底模教师读取题目及 gold CoT，离线提取选定层的 K/V 目标并压缩到工作区长度；学生只读题目及工作区，用最终有效选项 CE + 选定层的压缩 KV 损失学习。应先在相同层、相同投影定义和可对齐的位置上验证目标是否有意义；原论文的逐层逐头 eviction 及损失权重不能未经验证直接照搬。另设 LOTUS 式按步骤/位置预测文字 token 的实验作为不同监督目标，不把两个辅助损失一次叠加。
4. **检查训练信号是否真被利用。** 固定掩码确保答案位置只能依赖题目与 latent 工作区，绝不读到 gold CoT；答案标签也不能在教师目标的构造阶段直接作为学生输入。优先对比同样的 latent 数量及循环层块下，`K=1`、`K=3` 的答案 CE-only 和 CE+压缩 KV；再比较已有的无 latent 循环及单次前向训练。监测辅助损失、最终答案 CE、不同轮次的直接答题准确率及同一权重的无循环消融；过程损失降低而答案不升，不满足阶段目标。
5. **再考虑数据及容量。** 当前大多数实验仅用 1024 个训练样本、3 个 epoch；原 GSM-MC 训练集有 7468 条。若小规模结构确实显示循环增益，再比较完整训练集、不同 latent 位置数及循环轮数。GLR 使用约 10K 条 CoT 和更大训练预算，其数字仅作研究背景，不可把增大数据后的收益直接归因于新结构。

上述结构是面向我们当前答案字母评估接口的设计假设，不是 GLR、LOTUS 或 KaVa 的直接复现。特别是长 CoT 到有限工作区的压缩方式、位置编码、KV 投影位置以及多轮共享层的对齐方式，都需要实施时明确；否则压缩 KV 损失也可能只是迫使模型模仿教师的几何形状，而不帮助解题。文字预测对照还需要明确步骤拆分及可见性，避免只学习表面措辞。

## 循环教师的新实验（2026-11-18）

两条路线都做，按下面顺序。每条先用相同的 1024 条训练样本、1024 条独立验证样本和 final-loop CE+KL 设置做快速验证。训练从原始 Qwen3-1.7B 开始；旧 CE+KL 检查点只作为对照。

1. **让隐状态能按查询读出中间量。** 从训练 CoT 中提取 `<<算式=结果>>`，排除最后一道算式，取结果后的自然语言短语当查询。例如 `48/2=24` 后的 `clips in May` → `24`。查询、算式及标签均不进入学生提示；查询只交给训练期小读出器，由它从每轮的 24 个工作区位置读取数值。一个问题可以有多个查询，轮数与 CoT 步号不绑定。用相同监督分别训练单轮和三轮，三轮检查点额外关循环评估；对比历史单轮 `492/1024`、三轮 `508/1024` 和同检查点关循环 `497/1024`。保存带状态/屏蔽状态的训练集查询准确率作为诊断；主指标是独立验证集的答题率。读出成功只说明存在可读信息，不能证明答案使用了它。执行入口：`scripts/run_workspace_query_comparison.sh`。
2. **改变循环计算的顺序（UpLoop 启发）。** 第一项验证结束后再实现。保持 `[9,18)`、每层总共调用三次、总计 46 层调用和 24 槽，比较块循环 `A-B-…-I-A-B-…-I-A-B-…-I` 与层内循环 `A-A-A-B-B-B-…-I-I-I`。先只改执行顺序，固定总深度和训练目标，并用无 damping 的块循环作匹配对照；如果随后引入可训练残差门控，单独做消融，避免把门控收益归因给执行顺序。评估原生路径和关闭额外层调用的路径。参考 [UpLoop](https://arxiv.org/abs/2610.25004)，论文结果不能直接外推到当前小样本设置。

## 第二阶段：无循环学生蒸馏

只有第一阶段通过门槛再启动。冻结已经证明更强的循环教师；教师只看推理时实际可用的题目/选项，生成自己的 latent 过程，不额外读取 gold CoT。学生从标准 Qwen/Qwen3-1.7B 或匹配的无循环起点训练，输入仍为题目/选项加 `Answer: (`，每层运行一次，不附加 latent 工作区。先用最终答案 CE + 强教师的选项分布/全词表 logits 蒸馏建立匹配基线；再逐项测试能否用训练期的轻量读出器把教师中间步骤信号传给学生的选定层/答案槽。跨路径直接做向量余弦或位移 MSE 必须单独论证：现有实验不能说明它们在同一个语义坐标系。

成功标准是学生在没有循环、没有 latent 位置、没有生成 CoT 的**相同推理接口**下，优于从原始 Qwen 训练的单次前向 CE/KL 对照，并保留教师相对该对照的一部分增益。若教师已明显更强而学生仍不提升，应转向研究学生的信息容量、可学习读出位置或蒸馏目标；若教师不强，应继续第一阶段，不通过调整蒸馏系数掩盖问题。

## 资源与执行约束

用户运行正式 GPU 实验；后续实现应提供训练完成后立刻运行评估的命令，并导出 `HF_ENDPOINT=https://hf-mirror.com`，使用 GPU `0,2`。当前常用配置为每 GPU batch 4、梯度累积 2、DP=2；不因为担心 OOM 就悄悄调小 batch。现存循环/联合训练的峰值 CUDA reserved 约 22.9/23.1 GiB，增加 latent 位置、同时保留多个 readout、或额外教师 forward 都可能超额。KaVa 启发的试验应优先离线准备、只加载训练所需的压缩教师目标，避免训练时让完整教师和学生的激活图同时常驻显存；还要控制保存的层、头及位置数量。实施时逐项检查激活图与 full-vocab logits 的保存方式：优先选择性投影有监督的位置、分段 forward/backward、必要的梯度检查点，并在正式训练前做匹配 batch 的显存试跑。不能将历史记录当成新设计不会 OOM 的保证。
